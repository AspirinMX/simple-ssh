# Simple SSH 开发计划

Simple SSH 是按项目管理主机的本地桌面工具。用户选择项目、添加 SSH 主机后，即可打开交互终端，或启动该主机的端口转发规则。

沿用仓库现有的 Tauri 2、React、TypeScript 和 Rust。项目配置保存在本机 SQLite 文件中。Rust 后端通过 `libssh-rs` 完成 SSH 握手、主机指纹校验、用户认证、终端会话和端口转发。

## 项目、主机和凭据

| 对象 | 首版设计 |
| --- | --- |
| 项目 | 支持新建、重命名和归档。每个项目有独立的主机列表，可设置默认 SOCKS5 代理。 |
| SSH 主机 | 保存别名、地址、端口、用户名和认证方式。支持编辑和跨项目移动。代理可选「继承项目」「直连」「指定代理」。 |
| 密钥 | 本机密钥库供多个项目共享。已有私钥按路径引用，移除引用时保留原文件。新生成的私钥用口令加密，存放在用户专属目录。 |
| 密码和口令 | 默认在连接时输入。用户选择记住时，将秘密写入系统凭据库，SQLite 只保存凭据标识。 |
| 转发规则 | 每条规则归属一台主机，记录转发方向、监听地址和端口、目标地址和端口。规则持久保存，运行状态随实际连接更新。 |

## 开发阶段与验收

按一名开发者、Windows 优先估算。第一阶段完成后，根据原生依赖的打包结果和代理连接的实测情况更新排期。

| 阶段 | 工作内容 | 验收标准 |
| --- | --- | --- |
| 1. SSH 核心验证（2–3 个工作日） | 在 Tauri 工程中编译并打包 `libssh-rs`。验证直连、经已有 SOCKS5 代理连接，以及加载带口令的 Ed25519 私钥。 | 在干净的 Windows 环境安装后，两种连接方式均能执行远程命令。代理连接按目标 SSH 主机的地址和端口校验指纹。 |
| 2. 项目和主机管理（2–3 个工作日） | 接入 SQLite，完成项目和主机管理、代理配置继承。 | 两个项目可分别保存名为 `web-01` 的主机。重启后配置保留。移动主机后，用户可查看实际生效的代理。 |
| 3. 交互终端（3–5 个工作日） | 前端使用 xterm.js，Rust 后端管理会话。支持密码和已有私钥登录、首次连接确认指纹、终端输入输出、窗口缩放和断开。 | 从项目中打开主机后可使用 `vim`、`Ctrl+C` 和中文输入。已知主机指纹改变时，在发送登录凭据前中止连接并显示指纹差异。 |
| 4. 密钥管理与生成（2–3 个工作日） | 使用 RustCrypto 的 `ssh-key` 生成 Ed25519 密钥并加密私钥文件。支持导入已有密钥、复制公钥、关联主机。SSH 认证通过 `libssh-rs` 执行。 | 用户在应用内生成密钥，将公钥部署到服务器后即可登录。删除一个项目后，其他项目仍能使用同一把密钥。 |
| 5. SOCKS5 与隧道（4–6 个工作日） | 支持无认证和用户名密码认证的上游 SOCKS5 代理，由代理解析目标域名。支持启停本地端口转发（`-L`）和远程端口转发（`-R`）。 | 能连接仅代理侧可解析的主机。代理失败时显示原因并终止连接。两种转发均能双向传输数据，停止规则或断开会话后释放监听端口。 |
| 6. 打包与回归（2–3 个工作日） | 验证安装、配置升级、多会话并行、网络中断、口令错误和端口占用。 | 在干净机器上从新建项目开始，完成密钥登录、代理连接和端口转发，重启应用后能用已保存的配置再次连接。 |

## SOCKS5 原型验证

Rust 先通过用户配置的 SOCKS5 代理请求连接目标主机，再将已连通的 socket 通过 `SshOption::Socket` 交给 `libssh-rs` 执行 SSH 握手。会话使用目标主机名和端口查找已保存的指纹。第一阶段在 Windows 安装包中验证 socket 的持有与释放，以及连接过程中取消操作的行为。[libssh-rs 连接选项](https://docs.rs/libssh-rs/latest/libssh_rs/enum.SshOption.html)

## 交付里程碑

- **第 7–11 个工作日**，交付可用终端。用户能按项目管理主机，使用密码或已有私钥登录。
- **第 15–23 个工作日**，交付完整首版，覆盖密钥生成、SOCKS5 代理连接、本地和远程端口转发，以及 Windows 安装包。
